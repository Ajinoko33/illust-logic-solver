# イラストロジックソルバー

イラストロジック(ノノグラム)を自動で解くツール。

## 使い方

1. `src/main/resources`に[ヒントCSV](#ヒントCSV)を配置
2. `./gradlew run`で実行
3. `viewer/viewer.html`をブラウザで開く
4. `out/YYYYMMDDhhmmss/result.csv`に出力された解答CSVをviewerで選択

### ヒントCSV

行ヒント・列ヒントをそれぞれ表す、2つのCSVファイル。

| ファイル名      | 内容   |
|------------|------|
| `rows.csv` | 行ヒント |
| `cols.csv` | 列ヒント |

## アルゴリズム

キューで「次に探索するライン(行または列)」を管理し、順番に処理する。

各ラインでは、「現時点のライン状態」とそのラインの「ヒント」より、新たに確定するマスがないか調べる。([ラインの調査](#ラインの調査))

確定するマスがあれば、そのマスを元にして新たに垂直方向のラインが確定してくはずなので、新たにキューに追加する。(行→列→行→列→...と調べていく)

キューが無くなったとき、全てのマスが確定していれば解けているので、解答を出力して終了。未確定マスがあれば、その時点の確定マスから新たに確定できないということなので、仮確定して背理法で進めていく。

### ラインの調査

以下の流れで調査する。(行の場合の例。列も行と同様)

1. 黒に確定するマスを見つける
   1. ヒント・現時点のライン状態を満たし、各黒マスが最も**左**になる配置(左配置)を見つける
   2. ヒント・現時点のライン状態を満たし、各黒マスが最も**右**になる配置(右配置)を見つける
   3. 左配置と右配置で、同じヒントで重なる部分があれば、その部分は黒で確定 (そのヒントは必ずそこを覆うため)
2. 白に確定するマスを見つける
   1. 確定したヒントは、その両端が必ず白
   2. 左配置で、「最も左の黒マス」より左側は必ず白
   3. 右配置で、「最も右の黒マス」より右側は必ず白

左配置の探索は、

- dp\[i][p] := ヒントiを位置pから始めると、その後全てのヒントが、現在のライン状態を満たして配置可能か (boolean)

というDPを後ろから解けば求められる。

dp\[i][p]の更新では、ヒントiの値をlとすると、区間\[p, p+l-1]を黒にするということなので、以下の条件を全て満たせば配置可能となる。

1. 現在のライン状態で、区間\[p, p+l-1]内に白マスが無いこと
2. 現在のライン状態で、位置p+lが黒マスでないこと (直後は必ず白)
3. 現在のライン状態で、位置p+lより後ろにある最初の黒マス位置(存在しない場合は最終マス)をbとすると、区間\[p+l+1, b]を満たすある位置qで、dp\[i+1][q] = true であること (後ろでヒントi+1以降が配置可能であること。ただし、黒マスがあれば、直近の黒マスをヒントi+iが含むこと)

条件1は、白マスの個数を累積和で前計算しておけば、O(1)で判定可能。条件2は、現在のライン状態からO(1)で判定可能。 条件3は、位置pより後ろにある直近の黒マス位置を前計算しておき、DPテーブルの累積和も持ちながらテーブル更新すれば、O(1)で判定可能。

DPテーブルを更新したら、先頭のヒントの配置可能位置から追っていき、左配置を構成していく。この処理は、ヒントと位置を同時に進めて辿れば、O(max(M,N))で行える。

右配置の探索は、左右逆転させて左配置の探索を適用すればOK。

## 計算量

M行×N列の問題では、

- 背理法なしで解ける場合: **O(MN(max(M,N)^2)log(M+N))**
- 背理法が必要な場合: **O((C+1)MN(max(M,N)^2)log(M+N))**
  - Cは背理法を用いた回数
  - つまり、最悪O(((MNmax(M,N))^2)log(M+N))

### 背理法なしで解ける場合の計算量導出

まず、キューに追加する回数を求める。初期状態では全ラインが調査対象なのでM+N回。マスが確定すると、垂直方向のラインをキューに詰めるので、結果としてキューを追加する回数は、(M+N)+MN回。

キューはライン調査の回数削減のため、順序付きSetで管理する。追加・削除にO(log(M+N))かかる。

次に、1ラインを調査する計算量を求める。左配置を見つける処理がボトルネックになる。右配置は左右(あるいは上下)逆転させて左配置と同じ処理をすれば良く、他の処理はO(max(M,N))で処理可能。

左配置の探索での前計算は、

- 白マスの個数の累積和は、O(max(M,N)) (条件1)
- 直近の黒マス位置、O(max(M,N)) (条件3)

である。

よって、左配置の探索は、前計算がO(max(M,N))、DPテーブル更新がO(max(M,N)^2)、構成がO(max(M,N))なので、合わせてO(max(M,N)^2)となる。

最後に、キューが無くなったら、全マスをチェックして解けているか調べており、その処理はO(MN)。

以上より、最終的な計算量は、(M+N+MN){O(log(M+N))×O(max(M,N)^2)}+O(MN) = O(MN(max(M,N)^2)log(M+N)) となる。

### 背理法が必要な場合の計算量導出

仮確定したら、その情報をもとに解き進めていく。背理法でロールバックする分だけ追加で上記ロジックで解くため、背理法を用いた回数をCとすると、O((C+1)max(M,N)^2)。

背理法でロールバックする回数は、全マスの高々MN回なので、最悪O(((MNmax(M,N))^2)log(M+N))。
